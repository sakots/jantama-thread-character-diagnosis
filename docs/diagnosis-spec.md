# おすすめ雀魂キャラ診断 — プロダクト仕様案

ステータス: **design-proposal / prototype-implemented**。質問・配点・類似度は診断用の設計値であり、過去ログから検証された性格分類ではない。

## 想定する利用者・体験

- じゃんたまスレの文脈を分かるユーザー向け。初見にも意味が通る文言を心掛ける。
- 8〜12問程度の四択または二択。結果画面で雀魂キャラを1名推薦し、次点も表示できる。
- 「公式にこのキャラがあなたに合う」という事実主張ではなく、娯楽的な相性診断。

## 属性案（実データ由来ではない）

1. `chat` — 雑談を楽しむ
2. `mahjong` — 麻雀や何切るを楽しむ
3. `character` — キャラ・画像・二次創作を楽しむ
4. `social` — 友人戦・交流を楽しむ
5. `humor` — ネタや冗談を楽しむ
6. `calm` — まったり過ごす

## スコアリングの案

- 各選択肢が0〜複数の属性に0〜2点程度を加点する。
- キャラ側の属性重み（0〜5）は**出典確認のうえ人手レビュー**で設定する。数値自体は公式設定ではなく診断用の仮説とし、根拠資料とレビュー済みかを別々に記録する。
- 各回答を合計し、属性ごとの到達可能な最大点で割った回答ベクトルと、キャラ重みを5で割ったベクトルのコサイン類似度で順位を決める。相性度は類似度×100を小数第1位に丸める。順位は丸め前の値、同点時はIDの辞書順で決める。
- 正規化による `0〜100` はゲーム内の公式データではなくアプリ内の**相対スコア**であることを表示。
- 同点時の安定した順序（キャラID順など）、データ欠損時のガード、回答変更時の再計算を実装。
- キャラの属性値が未検証の段階では「診断準備中」とし、もっともらしい結果を捏造しない。
- 現在のデータで完了できるのは回答の傾向集計まで。属性ごとの到達可能な最大点に対する割合を表示し、キャラ相性や実測されたスレ民の分類とは区別する。
- 全回答が0点の場合は相性を計算せず、傾向を判定できない旨を表示する。

## 実装案

- TypeScript + React + Vite。Zodによる実行時検証、UIに依存しない純粋関数、JSONによるコンテンツ管理。
- 自動テスト: 回答漏れ、欠損キャラ、同点、再現性、正規化、未知キー。
- モバイル対応、キーボード操作、適切なコントラスト、質問前後への移動。

## 画面構成

1. タイトルと注意（非公式・娯楽用）
2. 質問（進捗・戻る・回答）
3. 結果（推薦キャラ、相性、理由、スレ民風一言、リトライ）
4. 出典・この診断について（公式・スレ文化・設計値の違い）

## 静的ファイルでの公開

- ビルド時のベースパスは `./` とし、`dist/index.html` から同じディレクトリの `assets/` を参照する。
- `dist/` の中身をFTPで任意の公開ディレクトリに配置する。質問とキャラデータはバンドルに含め、別途JSON配信やサーバー処理を必要としない。
- 画面遷移はReact内の状態で管理し、サーバー側のURL書き換えを不要にする。HTTP/HTTPS配信を前提とし、ローカルファイルの直接表示は対象外。
- 配置の検証では、ドメイン直下と複数階層のサブディレクトリで、生成HTMLのJS/CSS参照が配置先の実在ファイルを指すことを確認する。

## 表示文の作り方

- 本文にはスレ独自の言い回しを少量使う。
- 著作物の長文転載、実ユーザー投稿のコピペ、攻撃的フラッドを避ける。
- 「公式設定からの引用」と「スレ内のジョーク」は分かるように表示する。

## 初期実装のデータ契約

- `data/questions.json`: 8〜12問。質問・回答のIDは各スコープで一意。属性は上記6種類に限定し、回答配点は0〜2。全体に `evidence` を付け、すべて診断用仮説であることを示す。
- `data/characters.json`: 公式紹介は `officialProfile`、スレでの扱いは `threadInterpretation`、診断重みは `traits` に分離。未確認は `null` のまま。各非null項目に `evidence` を持たせる。
- `evidence`: `status`（user-confirmed / prior-analysis-summary / design-proposal / unverified）、`verified`、`source`、`confidence`（high / medium / low）。`verified` はその項目の事実確認を示す。別の `traits.reviewed` は診断用設計値の人手レビューを示し、事実確認とは混同しない。
- `traits`: `{ weights: { 全6属性: 0〜5 }, reviewed: boolean, evidence }`。対象は `universe: mahjong-soul`、`eligibleForDiagnosis: true`、`reviewed: true`、非ゼロベクトルで、非nullの公式紹介とその確認済み出典が必要。スレ内の扱いだけから公式性格を作らない。
- `threadMemeCharacters` は参考情報で、推薦候補に混ぜない。福丸小糸のゲーム内での登場状況は未確認で、既存の区分はスレ資料の整理用として扱う。
- `data/presentation.json`: 属性の表示名、結果の一言、説明文を管理。一言は創作文で、実投稿や公式台詞として扱わない。
- データ構造不備は起動時に検出し、画面に読み込みエラーを出す。未完了回答と未知の質問・回答IDは計算を拒否する。レビュー前キャラや非表示IDは候補から除外し、候補0件は準備中にする。
- 推薦理由は類似度への寄与が大きい最大2属性を示す。根拠のないキャラ評や人気順位は生成しない。
