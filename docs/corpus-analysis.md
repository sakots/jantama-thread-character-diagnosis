# ログ再検証の方法

## 対象の確定

- `corpus/*.json` の `thread_array` を読み、レス行数と形式を棚卸しする。公開用には投稿者のID・名前・IP・ワッチョイ・外部リンク・本文を出力しない。
- 起点は今回確認したPart3099のログ。第1レスの「前スレ」以降から麻雀板のスレリンクを抽出し、参照先を再帰的に辿る。
- 前スレ欄には複数の過去スレが記載される場合があるため、すべてを参照グラフとして辿る。到達したログを対象集合とし、全件が唯一の本流であるとは断定しない。
- タイトルの改変やSikiの `part_est` だけから番号を補わない。明示的なPart表記の範囲と未確定タイトルの件数を分ける。未収録リンク、複数参照、同番号のスレを内部記録に残す。
- 末尾スラッシュなし、モバイルURL、ログ中の `t...ad.cgi` / `t...d.cgi` の省略形に対応する。省略URLでも残っているスレIDから参照を辿り、外部URLを復元・取得しない。

## 集計と除外

- 集計は読み込めたレス単位。スレごとの重複レス番号は除去する。
- レス1〜5のテンプレート、1001以降の終了行、空本文を対象から除く。
- リンクを含む投稿、50行以上または1,000文字以上の長文、罫線・ブロック文字を含むAA候補、グロを直接示す語を含む投稿は、荒らし判定が未完成のため保守的に保留する。画像やリンク先は取得しない。
- 同一スレ内で20回以上反復された30文字以上の本文はフラッド候補として保留する。`おばさん` という単語だけでは除外しない。
- 保留には通常の画像反応や長文も含まれ、荒らしの完全な検出を保証しない。保留件数と理由を記録し、集計母数を明示する。
- 文字列辞書によるレス言及数を数える。各項目は1レス1件、分類は重複可能。話題の割合やキャラ人気・好感度を表す指標とはしない。
- 顔文字や語尾の出現だけから、投稿者のキャラや公式性格を推定しない。スレ内扱いは本文サンプルを照合してから要約する。

## 成果物と検証

- 内部成果物はGit管理外の `corpus/analysis/` に置く。根拠のスレID・レス番号と短い匿名化抜粋はここだけに記録する。
- 公開資料 `docs/corpus-report.md` は集計・方法・限界のみ。公開アプリの出典はこの資料を参照する。
- 生ログ照合済みの情報は `corpus-verified` とし、検証できた内容だけ `verified: true` にする。質問・配点・属性重みは引き続き `design-proposal`。
- `pnpm analyze:corpus` で再集計する。公式プロフィールの確認や診断重みのレビューは別作業とし、ログ投入だけで推薦を有効にしない。
- テストではHTML解析、複数前スレ参照、循環、対象外ログ、重複レス番号、保留条件、通常の「おばさん」の保持、辞書のレス単位集計、公開レポートへの本文漏れを検証する。
